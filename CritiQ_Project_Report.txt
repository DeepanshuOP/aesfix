================================================================================
SECTION 1 — PROJECT OVERVIEW
================================================================================

PROJECT TITLE:
  CritiQ — Hybrid Neuro-Fuzzy Image Aesthetic Evaluation System

PROBLEM STATEMENT:
  Automated image aesthetic assessment is a challenging task because aesthetic
  quality is inherently subjective. Existing deep learning approaches (NIMA,
  ViT-based models, AestheticViT) require large labeled datasets, GPU inference,
  and are opaque black boxes with no explainability. Furthermore, they cannot
  leverage textual photo critiques as signals — only raw pixel data.

  The core problem CritiQ solves:
    "Given one or more textual critiques of a photograph (and optionally the
    image itself), compute a structured, explainable aesthetic quality score
    and actionable improvement suggestions — with NO external API calls and
    NO GPU requirement in the default mode."

PURPOSE AND MOTIVATION:
  - Competes against RPCD baselines: NIMA (SRCC=0.12), ViT+Linear Probe (0.172),
    AestheticViT (0.25)
  - Designed as a lightweight, transparent, production-ready critique system
  - Useful for photographers seeking automated feedback on their work
  - Academic context: originally built on top of the RPCD (Reddit Photo Critique
    Dataset) framework by Nieto et al., NeurIPS 2022
  - Fully local operation: zero dependence on external paid APIs in default mode

EXPECTED FINAL OUTCOME:
  A complete, end-to-end pipeline that:
    1. Accepts text critiques and/or image files as input
    2. Extracts 5 aesthetic feature dimensions per critique
    3. Aggregates multi-critique signals with disagreement scoring
    4. Evaluates aesthetic quality via a Mamdani fuzzy inference system
    5. Produces a quality label (HIGH / MEDIUM / LOW) with confidence score
    6. Generates a template-based natural language explanation
    7. Provides actionable counterfactual improvement suggestions
    8. Benchmarks against SRCC/PLCC metrics vs baseline models

SECTION 2 — CURRENT APPROACH AND ARCHITECTURE
================================================================================

OVERALL SYSTEM DESIGN:
  CritiQ is a hybrid pipeline combining three paradigms:
    A. Rule-Based NLP (primary feature extractor from text)
    B. OpenCV Computer Vision (image-based feature extractor)
    C. CLIP Visual Encoder (deep learning image model — fallback/optional)
    D. Mamdani Fuzzy Inference System (quality evaluator)
    E. Template-Based NLG (explainer + counterfactual generator)

  The system is deliberately designed to be ZERO API — no Gemini, OpenAI, or any
  external calls required. Gemini API integration exists as a secondary fallback
  only for cases where rule-based extraction returns all-neutral scores.

ALGORITHMS AND MODELS USED:
  1. Rule-Based Keyword Scoring:
     - Each of 5 aesthetic dimensions (composition, lighting, color,
       subject_clarity, technical) has a curated positive and negative keyword
       list (approx. 12-15 keywords each).
     - Score = 0.3 + (pos_count / total_count) * 0.6
     - Neutral = 0.5 (if no keywords matched)

  2. OpenCV Feature Extraction:
     - Lighting: Mean pixel brightness; ideal = 0.4-0.6 range
     - Technical (Sharpness): Laplacian variance normalized to [0, 1]
     - Color: Mean HSV saturation * 1.5, clipped to [0.01, 0.99]
     - Composition: Canny edge density at rule-of-thirds positions
     - Subject Clarity: Std dev center vs border region ratio

  3. CLIP Encoder (optional, in pipeline mode):
     - Model: openai/clip-vit-base-patch32
     - Lazy-loaded; sigmoid of first 5 embedding dimensions mapped to features
     - NOTE: This approach is a placeholder mapping — not semantically grounded

  4. Mamdani Fuzzy Inference (scikit-fuzzy):
     - Universe: [0, 1] for all variables
     - Membership: triangular (low=[0,0,0.5], medium=[0,0.5,1], high=[0.5,1,1])
     - 14 rules covering strong positive, mixed, neutral, and negative combos
     - Defuzzification: centroid method
     - Label thresholds: HIGH >= 0.65, MEDIUM >= 0.40, LOW < 0.40

  5. Confidence-Weighted Aggregation (aggregator.py):
     - Certainty = |score - 0.5| * 2  (how non-neutral a score is)
     - Weighted average gives more weight to reviewer scores with stronger signals
     - Cosine distance between feature vectors as disagreement metric

KEY TECHNICAL DECISIONS AND REASONING:
  - ZERO API design: The Gemini API key field was deliberately made optional.
    Rule-based extraction is primary. No API quota needed to run.
  - Mamdani over Sugeno: Mamdani gives interpretable output membership functions,
    better suited for subjective/aesthetic domains.
  - Template NLG over GPT: Avoids API costs; produces consistent, attributable
    explanations that reference actual feature scores.
  - Caching: MD5 hash of critique text as key; persisted in cache/llm_cache.json
    to avoid reprocessing identical critiques.
  - CLIP mapping issue: The mapping of CLIP embedding indices to aesthetic features
    (composition=feat[0], etc.) is a heuristic — not semantically meaningful.
    This is a known limitation (see Section 4).

SECTION 3 — IMPLEMENTED COMPONENTS (DONE)

ALL COMPLETED FEATURES:

  [1] Rule-Based Text Feature Extractor (llm_extractor.py)
      - 5 dimension keyword dictionaries (composition, lighting, color,
        subject_clarity, technical)
      - _score_dimension(): keyword match -> 0.3-0.9 scaled score
      - _sentiment_score(): overall positive/negative sentiment
      - MD5 cache: saves and loads from cache/llm_cache.json
      - Gemini fallback: called only if all 5 scores are 0.5 (neutral) AND
        model is not None
      - configure_gemini(): API key setup for optional fallback
      - STATUS: Fully working, tested, zero-API by default

  [2] OpenCV Image Feature Extractor (image_features.py)
      - extract_image_features(image_path): returns 5-feature dict
      - Lighting from mean brightness
      - Technical from Laplacian variance (sharpness)
      - Color from HSV saturation mean
      - Composition proxy from Canny edge distribution at rule-of-thirds
      - Subject clarity from center vs border std dev ratio
      - Graceful fallback (returns 0.5 defaults if image fails to load)
      - STATUS: Fully working, tested on real images (test.jpg, bright.jpg, etc.)

  [3] CLIP Image Model (image_model.py)
      - Lazy-loads openai/clip-vit-base-patch32 via HuggingFace Transformers
      - Returns 5-feature dict from first 5 normalized CLIP embedding dims
      - Error-safe with fallback to 0.5 defaults
      - STATUS: Code complete; KNOWN BUG — 'BaseModelOutputWithPooling' attribute
        error when calling get_image_features() in current transformers version

  [4] Fuzzy Inference System (fuzzy_system.py)
      - build_fuzzy_system(): creates 5-input, 1-output Mamdani system
      - evaluate_aesthetics(): clamped inputs, returns (label, score)
      - 14 rules covering all major quality scenarios
      - Label thresholds: HIGH >= 0.65, MEDIUM >= 0.40
      - STATUS: Fully working, self-tested

  [5] Multi-Critique Aggregator (aggregator.py)
      - confidence_weighted_aggregate(): weighted by certainty distance from 0.5
      - compute_disagreement(): cosine distance between feature vectors
      - subjectivity_label(): LOW < 0.15, MODERATE < 0.35, HIGH >= 0.35
      - identify_aspect_driver(): finds best/worst dimension by label
      - STATUS: Fully working

  [6] Template Explanation Generator (explainer.py)
      - generate_explanation(label, score, features, model=None): pure template
      - Handles HIGH, MEDIUM, LOW labels with sub-cases based on score ranges
      - References actual feature scores in natural language
      - STATUS: Fully working, zero API calls

  [7] Template Counterfactual Generator (counterfactual_generator.py)
      - IMPROVEMENT_TIPS: 4 curated tips per dimension (5 dimensions = 20 tips)
      - generate_counterfactual(): selects tips for 2 weakest dimensions
      - HIGH path: maintenance advice; LOW/MEDIUM paths: targeted improvement
      - STATUS: Fully working, zero API calls

  [8] Pipeline Orchestrator (pipeline.py)
      - load_dataset(): JSON file -> list of dicts
      - run_pipeline(): processes N samples, handles text and image inputs
      - save_results(): writes JSON to results/
      - Handles both image-path items and text-critique items
      - Skips counterfactual in pipeline mode to save API quota
      - STATUS: Fully working

  [9] Main Entry Point (main.py)
      - Three modes: run, eval, single
      - --mode run: batch pipeline over dataset
      - --mode eval: evaluate existing results file
      - --mode single: single critique or image input
      - --image flag: direct image file path evaluation
      - Argument parsing: --api-key, --data, --output, --limit, --critique
      - STATUS: Fully working

  [10] Evaluation Module (evaluate.py)
       - Computes SRCC and PLCC against original sentiment scores
       - Label distribution analysis (HIGH/MEDIUM/LOW counts)
       - Label accuracy against ground truth
       - Comparison table vs NIMA/ViT+LP/AestheticViT baselines
       - STATUS: Fully working

  [11] Synthetic Dataset Generator (data/create_synthetic.py)
       - Generates 200 records: 67 HIGH, 67 MEDIUM, 66 LOW
       - Structured critique pool (8 critiques per tier x 3 tiers)
       - 15% cross-tier noise to simulate real disagreement
       - Splits: 140 train / 30 validation / 30 test
       - Outputs: processed_info_train.json, processed_info_validation.json,
         processed_info_test.json
       - STATUS: Done; files already generated and committed

  [12] LLM Cache Module (our_system/llm_cache.py)
       - get_cached(text): retrieves from MD5-keyed JSON cache
       - set_cached(text, result): persists to cache/llm_cache.json
       - STATUS: Working (functionality is also inlined in llm_extractor.py)

SECTION 7 — MODELS, DATASETS, AND DEPENDENCIES
================================================================================

MODELS:
  1. Rule-Based NLP (no model file):
     - Pure keyword matching with hardcoded lists in llm_extractor.py
     - No weights, no pretrained models
     - Instantaneous, zero memory

  2. scikit-fuzzy Fuzzy Inference System:
     - Built dynamically at runtime via build_fuzzy_system()
     - No external weights file
     - ~0.1 seconds to build

  3. OpenCV Feature Extraction (no model):
     - Standard OpenCV algorithms: Laplacian, Canny, HSV conversion
     - No pretrained weights

  4. CLIP (openai/clip-vit-base-patch32):
     - Downloaded from HuggingFace Hub on first use (~350MB)
     - Stored in HuggingFace cache (~/.cache/huggingface/)
     - Currently BROKEN due to transformers API version mismatch

  5. Google Gemini (optional fallback only):
     - Used only if all 5 feature scores are neutral AND API key provided
     - Model: gemini-1.5-pro (or installed version in google-generativeai)
     - Completely optional; system works without it

  Primary (currently used):
    - Synthetic RPCD-style dataset — generated by data/create_synthetic.py

IMPORTANT DESIGN NOTES:
  1. The fuzzy system (scikit-fuzzy) is the CORE evaluator. All feature extractors
     must output scores in [0, 1] range compatible with the 0.01-0.99 clamp.

  2. The 5 FEATURE KEYS are ALWAYS: composition, lighting, color,
     subject_clarity, technical. Any new feature extractor MUST return these
     exact keys (plus an optional "summary" string key).

  3. The rule-based extractor is the primary text pipeline. NEVER replace it.
     Only supplement with CLIP/LLM as fallback.

  4. The synthetic dataset (data/create_synthetic.py) was built to test the
     system WITHOUT needing real RPCD data. It mirrors the RPCD schema exactly:
     {id, image, comments[], sentiment_score, ground_truth_quality}

  5. cache/ directory stores processed critiques to avoid re-running. If you
     change the keyword lists in llm_extractor.py, delete cache/llm_cache.json
     to force re-extraction.

  6. The CLIP image model (image_model.py) is imported in pipeline.py as
     extract_image_features. The OpenCV version is in image_features.py.
     They have the same function signature and output format.
     To use the working OpenCV version in pipeline.py, change:
       from our_system.image_model import extract_image_features
     to:
       from our_system.image_features import extract_image_features

  7. In pipeline.py, counterfactual generation is explicitly SKIPPED with:
       counterfactual = "Skipped to save API usage."
     In final production mode, replace with:
       counterfactual = generate_counterfactual(label, agg, model)

     These are from the original published paper (Nieto et al. 2022) and should
     NOT be changed unless re-running on real RPCD data.

  9. Scoring range for rule-based: 0.30 to 0.90 (never 0 or 1)
     Scoring for neutral (no keywords found): exactly 0.50
